# 汇报素材索引与采集计划

当前为开发阶段素材，正式结果完成前不制作带有结论的最终 PPT。

协作约定：在整个项目过程中主动保存有汇报价值的运行结果、关键日志、对照案例与截图候选，正式结果稳定后再统一制作 PPT。可自动导出的材料由助手保存；需要用户亲自操作或截图的部分，保留具体运行命令、任务／运行 ID、应截取的画面和对应讲解目的，最后提供清晰清单，不要求用户自行回忆重做。

## 已保存的案例配图

- `01_baseline_clean.png`：原始 Agent 读取地址变更文件并更新账户信息，官方任务效用检查通过。
- `02_baseline_injected.png`：同一任务、相同基线模型，文件夹带修改密码指令；模型拒绝该指令并完成地址更新。
- `sources/`：以上两图对应的真实轨迹快照。
- `manifest.json`：原始日志位置、SHA256 与导出图的对应关系。

两张图为真实日志摘录的排版图，不是运行界面截图。均来自未加入我们新增防御的原始 Agent，不能称为“改进前后对比”。为适应幻灯片版式，部分长文本只展示摘录，完整内容保留在 JSON 中。

图中人名、地址、密码字符串均为 AgentDojo 模拟数据；不包含本机 API Key 或账户余额。

渲染入口为 `python -m course_project.export_presentation_evidence`，需要 Pillow 与可用的中英文字体；这是可选的素材导出依赖，不参与模型实验，也不调用 API。

## 后续需要采集的证据

| 素材 | 当前状态 | 用于说明什么 | 保留方式 |
|---|---|---|---|
| 系统流程图与攻击进入位置 | 待绘制 | 用户指令、工具内容、Agent 行动的关系 | SVG 或其他可编辑矢量格式 |
| 环境与版本摘要 | 已有原始记录 | 固定提交、benchmark、模型和参数 | 从 manifest 提取成表格，必要时截取一条简洁的检查输出 |
| 正常任务运行案例 | 已有一组配图 | Agent 能完成什么业务 | 原始轨迹、工具返回、结果判定与案例图 |
| 注入未成功的基线案例 | 已有一组配图 | 本例中模型的行为与证据 | 原始轨迹、摘录图与单次样例标签 |
| 正常任务失败案例 | 已有原始日志，待制图 | 日期缺失、追问与任务成功指标的关系 | task_0 轨迹；不归因为攻击或新增防御 |
| 注入成功或其他代表性失败 | 尚未观察到 | 具体失效机制与攻击范围 | 保留全部运行，按已说明的规则选择代表性案例 |
| 新增防御的工作位置与代码 | 尚未实现 | 主要修改究竟是什么 | 流程图、简短代码差异及对应提交 |
| 同任务、同攻击的配置对照 | 尚未开展 | 原始、现成防御、新增防御之间的区别 | 运行 ID 对照表、同格式案例图；若没有改善则如实展示 |
| 正式结果图表 | 尚未开展 | 效用、攻击成功、误拦截、token、耗时的取舍 | CSV/JSON 为源，PNG/SVG/PDF 为展示；保留样本量和重复次数 |
| 调试与修复证据 | 已有记录 | 可注入性检查和日志入口问题如何解决 | 失败输出、修复提交和回归检查；只选关键片段 |
| 1–2 分钟运行演示 | 正式版本稳定后录制 | 展示一次完整任务与关键决策 | 提前录制，避免最终讲解依赖网络即时响应 |

不要只保存终端截图。每张结果图必须能追溯到配置和日志。保留失败和未运行记录；截图中不显示 `.env` 内容、请求头或密钥。论文插图如果使用，标注论文与图号。

## 推荐的视频结构（约 12–14 分钟，8–10 页幻灯片）

1. 研究问题与具体复现目标。
2. AgentDojo 场景、工具流程与威胁模型。
3. 实验范围、环境、模型替换和比较限制。
4. 基线结果及关键失败模式。
5. 一项主要修改的动机与设计。
6. 对照实验设置、指标和结果图。
7. 一个可追溯案例与短演示。
8. 调试经验、局限、结论与建议。

页数和 12–14 分钟是我们的安排建议。老师明确要求的是最长 15 分钟的 Zoom 录制展示，并讲清复现目标、修改影响、有效／失效之处及经验建议；作业未单独要求提交 PPT 文件。
